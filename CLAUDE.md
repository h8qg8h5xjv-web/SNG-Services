## 1. Как ты работаешь со мной

Режим — рабочий. Пиши код сам, не жди подтверждения на каждый шаг.

- Короткий план в 3–5 строк, потом сразу выполняй. Не жди «ок».
- Доводи задачу до конца: код, типы, миграции, проверка сборки.
- Останавливайся и спрашивай только в трёх случаях: решение необратимое (удаление данных, смена схемы уже заполненной таблицы), нужна новая зависимость, требование противоречит этому файлу.
- Если моё требование неоднозначно — выбери разумный вариант, сделай и напиши в резюме, какое допущение принял. Не тормози ради уточнения.
- В конце каждой задачи — резюме: что сделал, какие файлы затронул, какие решения принял и почему. Коротко, без воды.
- Если я прошу что-то, что является плохой практикой — сделай, но скажи об этом в резюме.
- Не пиши комментарии-очевидности в коде. Комментируй только неочевидные решения.

## 2. Что за проект

**Название:** SNG Services

**Что это:** каталог и система бронирования услуг для русскоязычной аудитории в Великобритании. Салоны, мастера, гиды, репетиторы и подобное. Пользователь находит поставщика услуги и бронирует слот онлайн.

**Кто пользователь:** русскоязычный житель UK, в основном Лондон.

**Текущая фаза:** Фаза 1 — каталог + расписание + бронирование. Весь контент публикую я. Пользовательского контента нет.

**Чего в проекте НЕТ и пока не будет:** чатов, форумов, открытых комментариев, платежей. Не предлагай их и не закладывай под них структуру.


Новые папки верхнего уровня — только по согласованию.

---

## 5. Соглашения по коду

- TypeScript строгий. `any` запрещён. Если тип неизвестен — `unknown` и сужение.
- Имена файлов: `kebab-case`. Компоненты: `PascalCase`. Переменные и функции: `camelCase`.
- Таблицы и колонки в БД: `snake_case`, множественное число для таблиц (`providers`, `bookings`).
- Все запросы к Supabase — только в `/lib`. Компоненты не ходят в базу напрямую.
- Даты и время хранить в UTC (`timestamptz`). Часовой пояс — только на выводе.
- Деньги хранить целыми числами в пенсах. Никаких float.

## 6. База данных

- Любое изменение схемы — только через файл миграции в `/supabase`. Никаких правок через UI Supabase.
- Row Level Security включена на всех таблицах. Новая таблица без политики RLS — незаконченная работа.
- Перед созданием таблицы объясни мне модель данных: сущности, связи, ключи. Только потом SQL.
